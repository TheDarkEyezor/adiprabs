## The real cause wasn't `next-mdx-remote`

Next 15.5 bundles **React 19.2-canary** at `next/dist/compiled/react` for its server graph, while your userland React was **18.3.1**. Any library creating elements with the userland jsx-runtime on the server produced elements the server renderer rejected. That's what surfaced as "Invalid hook call ... more than one copy of React" — and when I first moved to the RSC entrypoint, it changed to the more explicit *"A React Element from an older version of React was rendered."*

So the fix was two parts:

1. **Aligned React to 19** (with framer-motion → 11.18.2 for React 19 support). Next 15 permits React 18 as a peer, which is why this never failed the build — it just quietly broke server rendering.
2. **Moved MDX to `next-mdx-remote/rsc`**, rendering the body in the server component and passing it into `BlogPostClient` as `children`.
