# The initial fear

Initially I was scared. I had the idea that vibe coding had essentially lowered the barrier to be a software engineer, or even the barrier to anything. The entire experience of going through schooling, college, picking up advanced skills, building projects independently, and exploring out of curiosity to develop a good understanding - all of it had just been made redundant by the advent of getting a really good probabilistic algorithm to predict the next token.

It's also played a part in lowering the intimidation that one faces when they want to take on making their own AI systems or a software-as-a-service. But I've come around to view vibe coding more as a tool to make good software engineers even better ones.

# The documentation nightmare

If anyone codes, they'll probably be able to relate to me when I say that I've spent days, hours on end, combing through Stack Overflow and documentation when trying to use an external library or API for a project. So much time spent on all the requests that need a steady hand to guide them to build a meaningful product.

When a software engineer is able to conceptually create a system or reason out the process when it comes to building a new app, a mind that is able to visualise the architecture - that's where vibe coding shines. LLMs can fill in the gaps, build the underlying skeleton, and fill in the required code to bring that idea to life.

# Debugging made faster

It's exceptionally useful in debugging, at least in my experience. I don't have to read through the entire stack trace to understand what's causing the error. It's faster for an LLM to find possibly where a bug is happening, run a fix or edit the files, and then test quickly whether that fixed the issue or not.

# The double-edged sword

I think LLMs are enabling faster and faster development, which could be a double-edged sword. With faster development you have more iteration, faster validation on ideas, and you're able to test them quickly. But it also risks overconfidence and trust in one's vibe coding agent to the extent that they push something out there that could lead to dangerous results.

I believe coding benchmarks have just recently passed 50% (I'll have to verify that), but it's important not to lean on them like a crutch. Rather, use them as something that could amplify your own thinking, bring ideas to existence quickly, validate them, and then move onto the next iteration from there.
